Requirement: Create a simple ad-hoc web application to help user view pokemon information. The app contains one screen display a list of pokemon information with:
+ Front image
+ Name
+ types.
Click on each item will popup a detail card with:
+ Front + back image
+ Name
+ Type 
+ Region
+ Weekness

Technical decisions: 
1. Monolith applicatoin consist of Be (java) and FE (React). Monorepo for both project.
2. Data should be fetch from https://pokeapi.co/. 
3. No DB invovled, BE fetch the data periodically and then cache the data locally. 
4. Testsuite: Test the MVP, we won't chase the coverage here.

UI Design: Located in ui_design folder
1. Each html should be corresponding with a component. The html was flatten, you'll need to analyze and link the connection between them.
For exmple detail_card.html actually reuse the type_badge.html, see the div which contains "grass" and "fire" content.
the same for main_page.html, it contain a list of summary_card.
The only exception is the detail_card, it's no reference by the main page yet. You need to do that yourself, the detail card should popup when user click on summary card.

Open questions:
1. https://pokeapi.co/ contains all the data but seems to provide it in different APIs, analyze it API document and check how many query we need to fetch enough information for summary list. The worst case maybe that we have to make one query for each pokemon summary.
2. Should we test BE only or also FE.

Your task:
1. Analyze and discuss the solution.
2. Write implementation plan for me to review. The plan should contains low-level class design, but with the class purpose, interface, mechanism only. No need specific code.
